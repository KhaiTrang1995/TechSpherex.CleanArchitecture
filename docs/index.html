What's included

The parts every service needs, already wired together

Each piece is plain code in your repository — no hidden framework, no commercial dependency in the request pipeline.

Clean Architecture

Domain, Application, Infrastructure and Api projects. Architecture tests fail the build when a layer reaches the wrong way.

Manual CQRS

Commands, queries and handlers as small interfaces. No mediator library, so nothing to license and nothing to debug through.

REST + gRPC

Minimal APIs with TypedResults and gRPC services call the same handlers. Scalar serves the OpenAPI 3.2 document.

Result pattern

Failures are values. A closed Error hierarchy lets the compiler check that every error kind maps to an HTTP and gRPC status.

Identity + JWT

ASP.NET Core Identity with JWT bearer authentication, refresh tokens and role-based authorization.

EF Core + PostgreSQL

Migrations, seeding and audit fields, with a config-only in-memory mode for demos and tests.

HybridCache

In-process L1 and Redis L2 behind an ICacheService abstraction, with stampede protection and tag invalidation.

Observability

OpenTelemetry traces, metrics and logs. Aspire dashboard in development; ELK and Grafana stacks as Docker Compose profiles.

Docker + Native AOT

Multi-stage Alpine image running as a non-root user, with a build argument that switches to a Native AOT publish.

Multi-tenancy

Shared-table scaffold: a marker interface, tenant resolution middleware and EF Core query filters to build on.

Skill agents

An interface-only agent pattern with an orchestrator and a sample skill, ready to connect to the LLM provider you choose.

Rule engine

Business rules declared in configuration with AND/OR logic and priorities, so thresholds change without a redeploy.

Architecture

Dependencies point one way: inward

Each project references only the layer beneath it. The domain has no infrastructure knowledge at all.

Api

REST endpoints · gRPC services · middleware · Scalar

depends on

Infrastructure

EF Core · Identity · JWT · cache · CORS · rule engine

depends on

Application

CQRS handlers · validators · abstractions for data, cache and rules

depends on

Domain

Entities · Result and Error · business rules

  • Enforced, not documented. Nine NetArchTest rules run with the test suite and fail when a layer references one above it.
  • One handler, two transports. REST endpoints and gRPC services are thin adapters over the same command and query handlers.
  • Errors the compiler understands. Error is a C# 15 closed hierarchy, so a new error kind without a status mapping is a build warning.
  • Swappable edges. Handlers depend on IAppDbContext and ICacheService, never on PostgreSQL or Redis packages.

Quick start

Running in a minute

You need the .NET 11 SDK. Docker is only required for the PostgreSQL and Redis containers.

# No Docker: database and cache live in RAM, data is lost on exit
git clone https://github.com/KhaiTrang1995/TechSpherex.CleanArchitecture.git
cd TechSpherex.CleanArchitecture
.\scripts\start.ps1 -InMemory

# Full stack: PostgreSQL + Redis containers
.\scripts\start.ps1

# Dashboard over plain HTTP when the dev certificate is not trusted
.\scripts\start.ps1 -InMemory -Http
git clone https://github.com/KhaiTrang1995/TechSpherex.CleanArchitecture.git
cd TechSpherex.CleanArchitecture

# Starts PostgreSQL, Redis, the API and the Aspire dashboard
dotnet run --project src/AppHost

# Same, without containers
dotnet run --project src/AppHost -- --UseInMemoryStores=true
# Run from the repository root
docker compose up -d --build                    # API + PostgreSQL + Redis
docker compose --profile grafana up -d --build  # + Loki, Tempo, Prometheus, Grafana
docker compose --profile elk up -d --build      # + Elasticsearch, Logstash, Kibana

# Native AOT image
docker build --build-arg PUBLISH_AOT=true -t techspherex-api:aot .
dotnet build src/TechSpherex.CleanArchitecture.slnx
dotnet test --solution src/TechSpherex.CleanArchitecture.slnx

Then open the Aspire dashboard from the login URL printed in the console, and the API reference at https://localhost:7200/scalar/v1.
